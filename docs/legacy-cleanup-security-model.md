# 旧版清理的删除安全模型

Mac Face Lock 只清理已精确识别、用户明确确认且预检清单覆盖的六个旧版目标。
所有遍历和变更都绑定到已打开的目录描述符，并拒绝符号链接、硬链接、所有者
变化、根目录替换、超出条目或字节预算，以及发行版数据目录重叠。

## Darwin 系统调用边界

本机 Darwin `unlinkat(2)` 文档明确说明：删除目标由目录文件描述符与相对
**路径名**共同确定。系统不存在按 inode 或文件描述符删除目录项的接口。
`removefile(3)` 同样是按路径名工作。因此，检查 inode 后再调用 `unlinkat`
无法在系统调用层面形成“按已检查 inode 删除”的单一原子操作。

实现采用两层原子隔离来缩小并审计这个边界：

1. 清单目标先使用 `renameatx_np(..., RENAME_EXCL)` 移入不可预测的私有
   tombstone 名称，并重新验证被移动对象的 inode、类型和文件版本。
2. 在任何删除开始前，系统就为每个清单项生成唯一的 purge 路径，并把精确
   路径、身份、类型与普通文件版本写入清理日志。日志采用有界的精确 JSON
   schema，以 `0600` 权限通过同目录临时文件、同步和原子替换持久化。
3. 每个最终子项或 tombstone 根在删除前再次使用 `RENAME_EXCL` 移入日志中
   已记录的不可预测 purge 名称，并再次验证移动后的对象。
4. 恢复时，原路径、tombstone 路径和 purge 路径必须处于互斥状态。若中断
   发生在最终重命名及父目录同步之后，新进程只会重试日志中记录的精确 purge
   路径；普通文件必须继续匹配身份、类型、大小与修改时间，目录必须匹配身份
   和类型且在删除时为空。任何不匹配的替换对象都会保留并使清理失败关闭。
5. 完成标记写入前，系统会审计六个固定原目标、全部 tombstone 根和日志中的
   全部 purge 路径都已不存在。恢复不会扫描隐藏文件名，也不会通过前缀搜索
   猜测可能的 purge 文件。
6. 若最终移动得到的 inode 不匹配，代码尝试把该对象原子恢复到原名称；
   恢复失败时也不会删除它。
7. macOS 26 及以上版本中，普通文件的最终 `unlinkat` 同时使用
   `AT_UNIQUE` 与 `AT_NODELETEBUSY`，目录使用 `AT_NODELETEBUSY`，从而
   拒绝多硬链接文件和仍被打开的对象。macOS 12–15 的 SDK 与内核没有这两个
   标志，因此这些系统使用标准 `unlinkat` 标志；两层隔离、移动后身份验证、
   精确日志和失败关闭边界保持不变。

## 不宣称的保证

最终 `unlinkat` 仍按私有 purge 路径名解析。实现不宣称可以抵御已经取得
同一用户权限、能够实时发现不可预测 purge 名称并在最后一次验证与
`unlinkat` 之间替换它的主动对手。该残余窗口受不可预测名称、描述符相对
操作、所有者/硬链接检查和最小暴露时间限制，但不是 inode 原子删除。

自动测试在原公开名称的最终删除窗口注入文件与目录替换，证明替换 inode
会被检测并保留；测试不会把上述系统调用限制描述成不存在的保证。
