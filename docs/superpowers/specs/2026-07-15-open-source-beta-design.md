# Mac Face Lock 开源源码 Beta 设计规范

日期：2026-07-15
状态：已确认，等待实施
许可证：MIT License
目标版本：`v0.1.0-beta`

## 1. 目标

将当前只能在开发者本人 Mac 和固定目录运行的 Mac Face Lock，调整为可公开发布、可由其他 macOS 用户自行克隆、构建和安装的源码 Beta 项目。

首个开源版本只发布源码，不提供由项目维护者签名或 Apple 公证的 `.app`、DMG、PKG、自动更新或 App Store 分发。使用者负责在自己的 Mac 上构建应用并授予摄像头、输入监控和辅助功能权限。

## 2. 产品定位与安全边界

Mac Face Lock 是离开 Mac 后的辅助保护工具，不是 macOS 登录认证、FileVault、系统锁屏密码、Touch ID 或专业门禁系统的替代品。

当前人脸判断基于 OpenCV 人脸检测、灰度人脸模板和相似度阈值，没有活体检测、深度感知或照片防伪能力。公开资料必须明确说明：攻击者可能使用照片、视频、相似人脸或环境干扰绕过或误触发验证。项目不得宣称具备高安全等级、生物识别认证合规或防伪能力。

现有安全策略保持不变：

- 摄像头不可用时保持 Mac 解锁，不得把摄像头故障当成陌生人。
- 暂停保护时不验证、不锁屏，但后台状态和界面保持可见。
- 人脸模板、活动记录、状态、日志和证据默认仅保存在本机。
- 锁屏冷却和摄像头错误冷却均不得低于 300 秒。
- 卸载服务不得删除用户本地数据。

## 4. 可移植安装架构

### 4.1 项目路径

项目可以位于当前用户有读写权限的任意目录。运行时项目根目录必须来自以下可靠来源之一：

1. 安装脚本根据自身位置计算出的绝对路径；
2. LaunchAgent 启动参数传入的绝对路径；
3. 开发命令根据脚本自身位置计算出的路径。

Swift 界面不得包含开发者本机目录作为回退值。缺少有效项目路径时，界面应显示可理解的启动错误并退出，不能静默读取错误目录。

### 4.2 LaunchAgent 生成

仓库中的 plist 改为不含个人路径的模板。安装脚本在临时目录生成两个最终 plist，将当前仓库绝对路径、当前虚拟环境 Python 路径和日志路径写入生成文件，然后再复制到 `~/Library/LaunchAgents/`。

生成过程必须：

- 正确处理空格、中文和 XML 特殊字符；
- 使用 `plutil -lint` 验证生成结果；
- 保留现有事务式安装和失败回滚；
- 拒绝从 Git 工作树安装的保护逻辑应基于“是否为主工作区”，不能依赖固定用户名或固定目录；
- 不修改仓库中已提交的模板文件。

### 4.3 Python 运行时

`scripts/bootstrap.sh` 使用当前可用的 `python3` 创建 `.venv`。Agent 启动器使用 `.venv/bin/python`，不得复制或依赖固定的 Command Line Tools Python 3.9 可执行文件或固定的 `site-packages` 路径。

Agent App 仍作为权限和菜单栏不可见的运行容器，但其启动器应在运行时定位项目根目录和 `.venv/bin/python`。如果虚拟环境缺失或 Python 不可执行，必须记录明确错误并退出；LaunchAgent 可以继续负责重启。

## 5. 通知、隐私与本地数据

外部通知默认关闭：

- 默认配置将 `event_notify_on_lock` 设为 `false`。
- 默认配置不包含开发者机器上的通知脚本路径。
- 用户可以在本地配置中填写一个可执行脚本路径来启用通知。
- 通知脚本接口保持现有参数协议，但被视为用户自行配置的扩展点。
- 通知失败不得阻止锁屏或破坏 Agent 主循环。

`.gitignore` 必须继续排除以下本地数据：

- 人脸模板；
- 状态和控制文件；
- 活动时间线；
- UI 偏好；
- 日志；
- 摄像头或屏幕证据；
- 虚拟环境和构建产物。

公开前检查当前提交和完整 Git 历史，确认没有人脸模板、真实证据图、日志、访问令牌、私钥或密码。

Python 依赖使用完全固定的版本，保证 CI 和本机构建可复现。第三方说明至少列出：

## 9. 测试设计

所有行为修改按测试驱动方式实施。

新增或调整的自动化测试必须覆盖：

- 从包含空格和中文的临时项目路径生成有效 LaunchAgent；
- 生成结果引用当前项目路径和 `.venv/bin/python`；
- 仓库模板和应用源码不包含开发者个人绝对路径；
- 安装保护允许任意主工作区，拒绝链接工作树；
- 通知默认关闭且空脚本路径不会执行外部命令；
- 显式配置通知脚本后仍能按既有协议调用；
- Agent App 不依赖固定 Command Line Tools Python；
- Swift 界面缺少有效项目路径时明确失败；
- `.gitignore` 排除全部本地隐私数据；
- README 和发布文档不承诺活体检测或高安全认证。

现有 77 项 Python 测试、Swift 数据烟雾测试、Swift 类型检查、两个 App 构建、plist 校验和签名校验必须继续通过。

## 10. 错误处理

- `python3`、`.venv`、必要系统工具或本人模板缺失时，脚本应输出单一、可执行的修复建议。
- plist 生成或校验失败时，不得更新用户 LaunchAgent。
- 新服务启动失败时，安装脚本必须恢复安装前的两个服务配置。
- 外部通知配置无效时，只记录通知失败，不影响本地锁屏决定。
- 摄像头不可用时继续执行 fail-open 策略。
- UI 项目路径无效时不得创建或覆盖任意位置的数据文件。
