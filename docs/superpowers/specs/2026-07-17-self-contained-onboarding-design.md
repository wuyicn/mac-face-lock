# Mac Face Lock 自包含安装与首次启动设计

日期：2026-07-17  
状态：已确认，等待书面复核

## 目标

把当前面向开发者的源码 Beta 调整为面向普通 Mac 用户的开源自助 Beta。客户不需要 Codex、Python、Xcode Command Line Tools 或终端知识，即可从 GitHub Releases 下载应用、完成权限授权、录入本人、执行安全测试并主动开启保护。

本阶段不包含 Developer ID 正式签名和 Apple 公证。发行包使用临时签名，因此首次打开时仍可能需要在 Finder 中右键选择“打开”。

## 已确认的产品决策

- 交付完整离线包，内置运行组件；不在首次安装时联网下载依赖。
- 保留现有 Python、OpenCV 和 NumPy 识别核心，避免重写后重新承担识别准确率和安全回归风险。
- 未完成设置时保护默认关闭。
- 只有在必需权限、本人模板、后台服务和安全测试全部通过后，客户才能明确点击“开启保护”。
- 运行时继续默认离线，人脸模板、设置、记录、日志和证据保存在本机。
- 摄像头故障继续采用 fail-open：保持解锁并显示警告，不能把设备故障判断为陌生人。
- 源码开发模式继续保留，贡献者仍可使用现有脚本和测试。

## 用户安装流程

1. 客户从 GitHub Releases 下载 Apple Silicon 离线压缩包及 SHA-256 校验值。
2. 客户解压并将 `Mac Face Lock.app` 拖入“应用程序”。
3. 首次打开时，未公证版本可能需要在 Finder 中右键选择“打开”。
4. 应用发现设置尚未完成后，直接显示首次启动向导；后台保护保持关闭。
5. 客户依次完成准备检查、权限授权、本人录入、安全测试和完成确认。
6. 所有必要条件通过后，客户点击“开启保护”。
7. 应用安装并启动当前用户的后台服务；以后登录 Mac 时自动运行。

## 首次启动向导

### 1. 准备检查

应用检查以下条件：

- 处理器为 Apple Silicon。
- macOS 版本不低于 12.0。
- 应用位于 `/Applications` 或当前用户的 `~/Applications`。
- 应用资源和内置运行组件完整，版本清单与校验信息可读取。
- 应用支持目录可创建并写入。

不满足条件时，页面显示具体原因和可执行的修复操作。准备检查失败时不得安装后台服务。

### 2. 权限中心

权限中心展示真实状态，而不是只展示说明文字：

| 权限 | 是否必需 | 操作 |
| --- | --- | --- |
| 摄像头 | 必需 | 请求系统授权；被拒绝后打开摄像头隐私设置 |
| 输入监控 | 必需 | 请求检查；打开输入监控隐私设置 |
| 辅助功能 | 必需 | 请求检查；打开辅助功能隐私设置 |
| 屏幕录制 | 可选 | 仅在启用屏幕截图证据时请求 |

每项权限使用 `未开启`、`等待重新启动`、`已开启` 三种用户状态。应用定时重新检测，并在从系统设置返回前台时立即刷新。

后台识别组件与可见控制中心的权限分别检测。界面必须明确指出实际需要授权的应用名称，不能因为控制中心获得权限就错误地声称后台组件已经可用。

macOS 系统授权始终由客户本人完成。应用只负责请求授权、打开正确的系统设置页面和解释后续操作，不尝试绕过 TCC。

### 3. 录入本人

录入在应用内启动并显示进度，不要求客户执行脚本。引导依次覆盖：

- 正脸
- 左转约 30 度
- 右转约 30 度
- 轻微低头
- 轻微抬头

界面显示光线、是否检测到多张脸、脸部大小和当前采样进度。质量不足时，只要求重新完成失败的姿势。

采集期间的临时画面保存在应用支持目录下的临时区域，完成或取消后删除。最终只保留本地特征模板。新模板先写入临时文件，通过形状、有限数值和本人复核后再原子替换正式模板；失败时继续保留旧模板。

### 4. 安全测试

安全测试验证：

- 后台组件可启动。
- 摄像头可打开。
- 本人模板可读取。
- 当前使用者能够通过本人验证。
- 输入监控和辅助功能权限对实际后台组件有效。
- 数据目录、控制文件、状态文件和日志目录可读写。

测试模式不得调用真实锁屏。测试结果必须区分权限问题、摄像头占用、模板问题、后台服务问题和文件权限问题，并为可修复项目提供按钮。

### 5. 完成并开启

完成页汇总必需权限、本人模板、后台服务和安全测试状态。只有所有必需项目通过时，“开启保护”按钮才可用。

点击后应用：

1. 原子写入启用状态。
2. 安装或更新当前用户的后台启动项。
3. 启动后台服务。
4. 确认服务连续稳定运行。
5. 显示保护已开启的最终状态。

任何一步失败时回滚本次服务变更，并保持保护关闭。

## 日常设置

现有外观设置保留，但设置页改为以下分区：

### 权限与运行状态

- 展示所有权限的当前状态。
- 提供请求授权、打开系统设置和刷新状态操作。
- 权限被撤销时显示明显警告。

### 本人资料

- 显示本人模板是否存在和最近更新时间。
- 提供“重新录入本人”。
- 新模板成功前不覆盖旧模板。

### 保护规则

- 展示保护是否开启。
- 保留暂停和恢复操作。
- 屏幕截图证据关闭时不要求屏幕录制权限。

### 服务诊断与修复

- 展示后台服务版本、运行状态和最近心跳。
- 提供重新启动、重新安装和查看日志。
- 修复操作必须保留客户数据。

### 外观

- 保留跟随系统、浅色、深色和三种强调色。

## 应用结构

发行版 `Mac Face Lock.app` 包含：

- 原生 SwiftUI 控制中心和首次启动向导。
- 隐藏的后台 Agent 应用。
- 由固定版本依赖构建的自包含 Python 运行组件。
- OpenCV、NumPy、pynput、PyObjC 及其运行资源。
- 默认配置、版本清单、许可证和第三方声明。

自包含运行组件提供明确的子命令边界：

- `agent`：持续保护和锁屏执行。
- `enroll`：录入本人并输出结构化进度。
- `diagnose`：检查摄像头、文件和运行组件。
- `verify-owner`：执行不锁屏的本人测试。

Swift 应用不解析面向人的终端输出，而是读取结构化 JSON 事件和明确退出码。每个命令都接收显式的数据目录和配置路径，发行模式不依赖源码仓库位置。

源码模式继续支持现有项目目录、`.venv` 和脚本，发行模式使用应用内部运行组件。两种模式共享相同的 Python 核心模块和配置语义。

## 数据位置

发行模式使用：

`~/Library/Application Support/Mac Face Lock/`

目录包含：

| 路径 | 用途 |
| --- | --- |
| `config/config.json` | 客户配置 |
| `data/owner_face.npy` | 本人人脸模板 |
| `data/state.json` | 后台状态 |
| `data/control.json` | 启用或暂停状态 |
| `data/activity.jsonl` | 活动记录 |
| `data/ui-preferences.json` | 界面偏好 |
| `data/onboarding.json` | 首次设置完成状态和版本 |
| `data/evidence/` | 可选本地证据 |
| `logs/` | 后台及安装日志 |
| `backups/` | 有界的配置与模板迁移备份 |

路径解析逻辑必须明确区分源码模式和发行模式，不能通过当前工作目录猜测。

## 已有源码版迁移

应用检测到现有源码安装时，向导提供导入：

- 配置
- 本人模板
- 界面偏好
- 活动记录

导入采用复制、校验、原子提交。旧目录不被删除或修改。导入失败时删除未提交的新副本并继续使用旧安装，不留下半迁移状态。

## 后台服务

后台服务仍使用当前用户级 LaunchAgent，不要求管理员密码。启动项必须指向稳定的应用安装位置和应用内 Agent，不再包含源码仓库、开发者主目录或 `.venv` 路径。

服务安装更新沿用现有事务式策略：

- 备份当前启动项和应用状态。
- 写入新启动项。
- 启动并进行有界稳定性检查。
- 成功后提交。
- 失败时恢复原状态。

应用被移动后，服务诊断应识别路径不一致并提供重新安装服务。

## 离线打包与发布

发布构建在 Apple Silicon macOS 环境中完成。构建过程：

1. 使用锁定版本创建干净运行环境。
2. 将 Python 入口和依赖构建为自包含目录式运行组件。
3. 构建 Swift 控制中心和后台 Agent。
4. 复制默认配置、运行资源、许可证和第三方声明。
5. 生成包含版本与文件校验值的构建清单。
6. 对完整应用执行临时签名。
7. 验证应用结构、最低系统版本、签名、运行组件导入和无开发者绝对路径。
8. 生成离线压缩包和 SHA-256 文件。

首版不声明已获得 Apple 公证。README 和 Release 说明必须准确解释首次右键打开步骤及安全限制。

## 错误和安全行为

- 未完成必需权限、未录脸或测试失败时，不能开启保护。
- 运行过程中必需权限被撤销时，后台进入暂停状态并报告原因。
- 摄像头不可用时保持解锁并显示警告。
- 测试模式不执行锁屏。
- 重新录脸失败时保留旧模板。
- 安装或服务更新失败时恢复旧服务状态。
- 卸载后台服务默认保留客户数据；彻底删除需要单独确认。
- 所有对外信息继续说明当前没有活体检测，不能替代密码、Touch ID、FileVault、MDM 或系统锁屏策略。

- 启动项不包含开发者绝对路径。
- 应用包含全部运行库、OpenCV 级联资源、配置和许可证。
- 临时签名和最低 macOS 版本正确。
- 压缩包校验值可复算。
- 服务安装失败能够回滚。

### 手工验收

在没有 Codex、Python 和 Xcode 的全新 Apple Silicon Mac 用户环境中验证：

1. 解压并首次打开应用。
2. 在离线状态完成向导。
3. 完成所有必需权限。
4. 在应用内录脸和执行不锁屏测试。
5. 主动开启保护。
6. 注销或重启后确认服务恢复。
7. 撤销一个必需权限并确认保护暂停和警告。
8. 恢复权限并确认可修复。
