# Mac Face Lock 首个开源 Beta 暂缓源码版自动迁移设计

**日期：** 2026-07-18
**状态：** 已由后续设计取代，仅保留为历史记录
**适用分支：** `codex/self-contained-onboarding`

> **已取代的边界（Superseded boundary）：** 本文记录的是曾考虑过的“暂缓迁移并保留旧安装”方案，不再是当前产品行为。现行边界以 [单向旧版清理设计](2026-07-18-one-way-legacy-cleanup-design.md) 为准：发行版严格识别已知源码测试版，取得客户确认后执行不可恢复的旧运行环境清理；未知或不完整结构不自动删除。

## 决策

首个开源 Beta 不自动发现、读取、复制或迁移现有源码测试版数据。

新安装继续执行完整首次设置流程，包括权限检查、重新录入本人、安全测试和后台服务健康验证。旧源码安装及其配置、人脸模板、界面偏好和活动记录保持原样，不删除、不修改、不标记为已迁移。

此决策取代原自包含首次设置设计中的“已有源码版迁移”要求，以及原实施计划的 Task 9 自动导入方案。

## 原因

自动迁移需要同时保证：

- 多进程互斥不会因锁文件或父目录替换而分裂；
- 任何进程崩溃点都能恢复到全旧或全新状态；
- 人脸模板和回滚副本不会残留在脱离路径的目录；
- 候选发现到用户确认之间，每个源文件身份和内容不被替换；
- 损坏、未知或矛盾事务日志不会被误清理或绕过；
- 恢复失败期间，首次设置不能继续写入正式数据。

多轮实现与独立复审表明，逐文件自动迁移为首个公开 Beta 引入了高于其用户价值的文件系统事务复杂度。重新录脸耗时较短，而错误迁移可能损坏现有设置或暴露敏感模板，因此首发应优先选择可证明安全的行为。

## 用户体验

首次设置“准备检查”页显示固定说明：

> 如果您使用过源码测试版，本版本不会自动读取或迁移旧数据。请重新录入本人并完成安全测试；原目录和数据将保持不变。

说明不依赖旧安装扫描，因此不会因读取 LaunchAgent、源码路径或旧文件而触发阻塞、权限请求或迁移恢复。

用户无需选择“导入”或“跳过”。准备检查通过后，流程正常进入权限中心、重新录入本人、安全测试和完成启用。

设置中心与主界面不提供自动迁移入口。

## 代码调整范围

从最终工作树移除自动迁移功能：

- 删除 `src/app/SourceDataMigrator.swift`；
- 删除 `tests/swift/SourceDataMigratorTests.swift`；
- 移除 `SetupCoordinator` 中的候选发现、迁移状态、恢复、导入和跳过逻辑；
- 移除 `OnboardingView` 中的导入卡、恢复卡和“跳过导入”操作；
- 移除 CI 中独立迁移测试目标；
- 保留 Task 8 已完成的权限、录脸、安全测试、服务修复和实时门禁逻辑；
- 不回写或清理任何可能已存在的源码版目录。

已经提交到功能分支的迁移实现保留在 Git 历史中，但通过新的提交从最终产品状态中撤出；不使用破坏性重置。

## 数据与安全边界

- 应用不扫描源码仓库、旧 LaunchAgent 或旧数据目录以寻找迁移候选。
- 应用不读取旧人脸模板，不创建迁移 staging、journal、rollback 或 backup。
- 应用不删除旧数据，也不提供“一键清理旧版”功能。
- 新版本只在自己的发行版 Application Support 路径内创建数据。
- 保护功能仍只有在当前版本重新录脸、本人验证、全部权限和后台服务健康后才能启用。

## 测试与验收

实施必须先增加失败测试，再删除生产迁移路径。

最低验收：

1. Swift 和结构测试证明产品代码中不再存在 `SourceDataMigrator`、`migrationDecision`、自动候选发现、导入、恢复或跳过入口。
2. 首次设置准备页包含固定旧版说明，且不要求用户作迁移选择。
3. 新用户可从准备检查继续到权限中心，不被迁移状态阻断。
4. 已完成用户的主界面、设置中心和服务修复路径不受影响。
5. 应用启动与切回前台不会访问源码测试版目录或旧 LaunchAgent。
6. 全量 Swift、Python、双应用构建、plist、签名、最低 macOS 版本和开源路径策略继续通过。

## 后续版本

若未来确有自动迁移需求，应单独设计为新的版本化数据存储方案，例如构建完整不可变数据代并通过一次原子提交切换，而不是恢复当前逐文件迁移实现。该工作不属于首个开源 Beta。
