# Mac Face Lock Agent 权限引导闭环设计

日期：2026-07-22
状态：已确认，采用方案 A

## 背景与根因

首次设置的“安全测试”同时承担了两件不同的事：安装并启动后台 Agent，以及确认 Agent 已获得摄像头、输入监控和辅助功能权限。现有安装逻辑只有在三项权限全部为真时才认为安装成功；否则等待稳定健康超时并回滚 LaunchAgent。

这会形成循环：Agent 必须保持运行，macOS 才能稳定登记它的独立权限身份；但权限未齐时安装程序会删除 Agent。回滚后界面只能显示三项“未确认”，即使用户已经为可见的 `Mac Face Lock` 应用打开权限，也不能代表后台 `Mac Face Lock Agent` 已获授权。

## 目标

- 将“服务已稳定安装运行”与“服务已获全部权限、可开启保护”分成两个状态。
- Agent 能在保护关闭的前提下持续运行，供 macOS 登记和刷新独立权限。
- 摄像头、输入监控、辅助功能缺少任意一项时，安全测试仍失败，“开启保护”仍不可用。
- 安装、授权和再次运行安全测试形成可恢复闭环，不要求用户进入应用包手工选择后台程序。
- 保留现有失败开放策略：摄像头或权限异常不得误锁当前用户。

## 非目标

- 不改变人脸匹配算法、阈值、录入流程或锁屏判定。
- 不自动修改 macOS 隐私设置，也不绕过系统授权。
- 不在本次修复中完成 Developer ID 签名、公证或正式发行渠道建设。
- 不合并或清理与本问题无关的分支和用户工作区改动。

## 状态模型

后台服务分为两层状态：

1. **响应正常（responsive）**：LaunchAgent 已加载，PID 与 Agent 上报一致，状态不是停止/监听器错误，心跳时间新鲜且心跳序号持续递增。
2. **保护就绪（healthy）**：在响应正常的基础上，Agent 实际上报摄像头、输入监控、辅助功能三项权限均为真。

安装成功只要求“响应正常”；安全测试和开启保护继续要求“保护就绪”。因此权限缺失不会触发安装回滚，但也不会降低最终安全门槛。

## 运行流程

1. 用户在安全测试中运行诊断。
2. 发行版安装或更新 LaunchAgent，并保持 `control.json` 中保护关闭。
3. 安装器观察同一非零 PID 和持续推进的心跳；满足后保留服务。
4. 协调器读取 Agent 的三项实际权限并显示逐项状态。
5. 权限未齐时，安全测试返回可操作提示，Agent 保持运行，用户从对应按钮进入系统设置。
6. 用户授权后再次运行安全测试；Agent 定期重新探测权限，三项通过后本人无锁验证继续执行。
7. 只有诊断、本人资料、本人验证、服务健康和必需权限全部通过，才允许用户主动开启保护。

## 错误与回滚

- 以下情况继续回滚到安装前状态：plist 无效、`launchctl` 操作失败、进程未启动、PID 不一致、心跳过期或不推进、Agent 报告停止或输入监听器错误。
- 仅缺少 TCC 权限时不回滚；保持保护关闭并提示用户完成 Agent 授权。
- 应用位置改变仍标记为需要修复，不能把旧路径的服务视为当前服务。
- 显式“重启服务”仍可使用 `kickstart -k`；安装成功后的 `RunAtLoad` 启动不重复 kickstart。

## 代码边界

- `src/app/ServiceManager.swift`
  - 为 `ServiceStatus` 增加明确的响应正常判定。
  - 安装稳定性检查使用响应正常判定，不再使用包含权限门槛的 `isHealthy`。
  - `isHealthy` 保持现有严格含义，继续服务于安全测试和开启保护。
- `tests/swift/ServiceManagerTests.swift`
  - 新增权限未齐但服务心跳稳定时安装成功且不回滚的回归测试。
  - 保留无心跳、心跳不推进、PID 变化和运行错误时回滚的测试。
- `SetupCoordinator` 与界面原则上不扩展职责；它们继续消费严格的 `isHealthy` 和逐项权限状态。只有测试证明提示无法表达新状态时，才做最小文案调整。

## 测试策略

先写失败测试，再实施最小修改：

- RED：稳定 PID/推进心跳但三项权限为假，当前安装应因 `unstableService` 失败；新期望为安装成功且保留 plist。
- GREEN：引入响应正常判定，并只替换安装稳定性门槛。
- 回归：相同状态的 `isHealthy` 必须仍为假；权限全部为真后才为真。
- 回归：非推进心跳、陈旧心跳、错误 PID、停止状态仍必须安装失败并回滚。
- 全量：Swift 单元测试、Python 测试、发行包结构/签名一致性检查和构建脚本全部通过。

## 本机验收标准

- 重建并安装当前分支应用后，安全测试首次运行不会因缺权限删除 LaunchAgent。
- `Mac Face Lock Agent` 在摄像头、输入监控和辅助功能设置中可被识别，界面逐项显示真实状态。
- 权限未齐时 `protection_enabled` 保持 `false`，鼠标或键盘输入不会触发锁屏。
- 三项权限开启后再次运行安全测试，可完成后台服务检查和本人无锁验证。
- 只有所有门槛通过后“开启保护”可用；启用后服务重启和状态心跳仍正常。
- 撤销任一必需权限后，产品不能继续宣称保护就绪，并保持失败开放。
