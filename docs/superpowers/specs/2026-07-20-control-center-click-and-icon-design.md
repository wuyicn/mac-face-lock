# Mac Face Lock 控制中心点击与应用图标设计

## 目标

让发行版控制中心成为可正常激活、可点击的 macOS 桌面应用，并用正式品牌图标替换系统空白占位图。调整不得删除或迁移现有录脸资料、设置和运行记录。

## 已确认方案

采用蓝色“人脸识别框＋安全盾牌”图标：

- 白色到浅蓝色的圆角底；
- 主体使用当前界面的蓝色强调色；
- 人脸识别框表达本地面容验证；
- 小盾牌表达安全保护；
- 不包含文字、照片或第三方品牌元素；
- 在 Dock、Finder、应用程序目录和安装包中均清晰可辨。

不采用仅有 Face ID 符号的极简方案，也不采用与当前界面不一致的高光玻璃立体方案。

## 点击故障根因与修复

安全测试按钮在系统辅助功能树中处于启用状态，但按钮事件没有进入安全测试逻辑。控制中心卡片使用覆盖整个内容区域的装饰性 `overlay` 边框；该边框参与命中测试，导致下层按钮无法稳定接收鼠标事件。

修复范围：

1. 控制中心继续以普通桌面应用运行，使用常规激活策略，并在 Dock 中显示。
2. Onboarding 和设置页所有覆盖交互卡片的纯装饰边框明确设置为不参与命中测试。
3. 不更改安全测试、权限检测、录脸或后台 Agent 的业务规则。
4. 不用重试、自动运行或绕过权限来掩盖按钮事件问题。

## 图标资产与构建

项目保存可审查的图标源文件和最终 `AppIcon.icns`。图标采用项目本地的确定性几何图形生成，不依赖在线服务或客户机器上的 Codex。

构建流程：

1. 图标源文件生成完整 macOS iconset 尺寸。
2. 生成并提交 `AppIcon.icns`。
3. 控制中心 `Info.plist` 声明 `CFBundleIconFile`。
4. `build-status-app.sh` 将图标复制到应用的 `Contents/Resources`。
5. 最终应用重新签名，Release ZIP 继续通过清单与签名验证。

后台 `Mac Face Lock Agent` 保持独立身份和现有权限记录；本次只为用户可见的 `Mac Face Lock` 控制中心增加品牌图标。

## 用户流程

1. 用户从“应用程序”或 Dock 打开 `Mac Face Lock`。
2. 控制中心成为前台应用并显示正式图标。
3. 用户单击“运行安全测试”，按钮立即显示“正在执行不锁屏安全测试…”。
4. 后续诊断、本人验证和 Agent 权限检查沿用现有流程。
5. 测试失败时继续显示现有可恢复错误，不触发锁屏，也不破坏录脸资料。

## 验证

自动验证：

- 回归测试确认控制中心使用常规桌面应用激活策略；
- 回归测试确认交互卡片的装饰边框不参与命中测试；
- 打包测试确认 `CFBundleIconFile` 和 `AppIcon.icns` 均存在；
- Swift 编译、Python 测试、签名校验、Release Bundle 测试全部通过。

本机验收：

- Finder、Dock 和窗口切换器显示正式图标；
- 单击按钮即可出现运行状态，不需要双击；
- 安全测试实际启动并进入本人验证；
- 原有 `owner_face.npy`、onboarding 进度和设置保持不变；
- 无 Codex、Python 或 Xcode 的客户仍可直接使用预构建发行包。

## 边界

- 不重新设计控制中心整体界面。
- 不改变人脸识别算法、阈值或权限要求。
- 不修改后台 Agent 的图标、Bundle ID 或 TCC 权限身份。
- 不在本次变更中加入自动更新、安装器或公证流程。
